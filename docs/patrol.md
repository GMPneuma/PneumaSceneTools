# Patrol

Vehicles stop when a moving token blocks their next step. They keep their route for up to five seconds, continue as soon as the step clears, and reroute if it remains blocked at the deadline. Stationary tokens are routed around immediately. Movement is identified through Foundry's active position/rotation animations and Patrol's movement reservations; a token merely having Patrol enabled is not enough. Future manual moves cannot be predicted. Planning may look past moving traffic, but actual steps still check every token's full collision area. The wait is temporary GM-client state and repeated token updates do not extend it.

Vehicle waypoint pauses can be disabled or set to a zero-duration range. In either case, arrival advances to the next leg in the same scheduler tick, including Loop wrap and Back & Forth endpoints. Native animation time already elapsed during a document update is not waited again. Obstacle clearance and bounded route planning may still delay movement. Local regression coverage; live Foundry retest pending.

Patrol moves scene tokens outside combat. A GM opens **Token Controls > Scene Tools - Patrol** (route icon) to show the compact, semi-transparent scene controller. It lists every token with saved Patrol settings, with Start, Stop and Edit buttons. The header pencil opens the editor for adding a patrol; each row pencil opens that token in the editor. The scene header uses a Play/Pause icon. Settings belong to that placed token, not its Actor or prototype.

## Modes

- **Loop:** visit waypoints in order and return from the last to the first.
- **Back & Forth:** visit waypoints in order, reversing at each end.
- **Random:** choose a reachable, unoccupied destination within the selected native Region, travel to it, then pause and choose another.

For Loop and Back & Forth, use **Place stops on map** to set token-center waypoints. Rows allow coordinate edits, reordering and removal. **Pauses at waypoints** enables a shared minimum/maximum pause duration. **Pauses along path** adds a separate duration range and a **Pause every** interval measured in seconds of movement on the current leg. Path pauses preserve the destination and continue afterward; they wait until the token has a clear stopping footprint. **Side tracks** enables occasional deviations, with a maximum distance in grid spaces from a clear segment of the planned path. Unsafe deviations are skipped; at most one is selected per leg. These options replace the separate Wandering route mode and per-stop pause values.

For Random, **Favor distant locations** prefers destinations at least four grid spaces away or half the longest Region dimension, whichever is larger, with nearby fallbacks. Disable it for unbiased candidate ordering. **Maximum movement time** limits each stretch of travel before pausing and choosing another destination; 0 means unlimited. If the time limit falls on an occupied position, travel continues until a clear stopping position. Random has its own pause-duration range. Region boundaries, holes, elevation and walls are checked. Movement uses linear segments up to one second, retaining the destination between updates. New obstructions trigger replanning; blocked destinations retain their safe approach route and are retried when no further safe progress is available.

Speed is in grid spaces per second (0.1–5); on gridless scenes it uses the scene's stored pixel grid size. It is an ambient animation speed, not a combat MOVE allowance.

**Save** saves settings and stops the token. **Start** saves settings and enables movement. **Stop** stops the selected token without saving editor changes. The controller has a **Stop scene / Start scene** toggle. Scene Stop suspends all movement without changing individual enabled/stopped settings; Scene Start resumes only individually enabled patrols. Individually stopped patrols remain stopped, including across reloads. Starting an individual patrol while the scene is stopped arms it for the next Scene Start. The editor Stop scene button uses the same scene pause. Changing tokens asks before discarding unsaved edits. Closing the editor or controller does not stop patrols; closing the editor removes its preview. Switching scenes closes the controller.

## Movement and occupancy

Pedestrian routing uses the whole rectangular footprint, including walls inside it and Region holes between its corners. Vehicle wall checks use the clipping tolerance described below; all non-wall checks retain the full footprint. It routes around movement-blocking walls and checks Foundry's native movement collision before submitting moves. Closed and locked doors block; open doors do not. Directional movement walls are conservatively blocked from both directions. Wall-height module flags are not interpreted by the footprint check. Tiles/furniture do not block travel unless walled.

Pedestrians can pass through other pedestrians. Vehicles and active vehicle movement areas block all patrols; vehicle paths also treat pedestrians as obstacles. A destination must have room for the entire token without overlapping another token or another patrol's reserved destination. The runtime checks again before arrival. A blocked destination does not prevent departure: the planner uses a safe partial route toward it, stops at the closest reachable position found by the bounded search, then retries. It retains the destination and does not count a partial route as waypoint arrival. When clearance returns, it continues. Random movement-time limits can still deliberately end a trip. If a token enters a paused patrol's space, the patrol cancels its dwell and attempts to relocate. No reachable free destination means waiting/retrying; the module never teleports through an obstruction. A completely packed/enclosed area or another user forcibly moving tokens can prevent relocation.

Routes use a bounded half-grid search to keep scene workloads finite. Extremely narrow or complex routes may be reported as unavailable; add intermediate stops or widen the route. At most 100 stops are supported.

## Vehicles

SceneTools vehicles (tokens stamped CreatedByVehicleTools) automatically use a driving planner. This applies to Loop, Back & Forth and Random on square or gridless scenes. Ordinary Actors named or typed as vehicles are not automatically classified as SceneTools vehicles.

- **Artwork front** is a vehicle-only setting: Up (0°), Right (90°), Down (180°), or Left (270°), describing the nose in the original unrotated image. For upside-down artwork choose Down. It calibrates forward movement without editing or immediately rotating the token artwork. Collision dimensions continue to follow actual artwork rotation. Start with unlocked rotation and a multiple-of-45-degree facing; otherwise Start explains the required correction.
- Each driving step goes to one of eight directions, with half-grid positioning available to line up with openings. Facing changes by up to 90 degrees during the move, favoring 45-degree turns when a modestly longer route has clearance; stationary 45-degree turns carry a high route cost so driving or reversing is preferred. Each stationary turn takes 250 ms, reserves its swept area, and must lead to a safe route onward. Reverse steps preserve the direction of the vehicle nose, rather than facing backward.
- Forward routes are preferred. A bounded search can use forward/reverse maneuvers when forward-only routing fails, with at most three consecutive reverse steps per planned sequence. If the destination cannot be reached, a safe partial route approaches it before waiting; no partial-route endpoint counts as arrival. No progress means waiting, not teleporting or forcing a turn.
- Waypoints and Random destinations use the nearest position on the vehicle's half-grid movement lattice. Diagonal steps cover a longer distance and take proportionally longer at the selected speed.
- Vehicle wall clearance allows up to a quarter grid square of edge clipping per side (half a square less overall width/height). A three-square-wide vehicle can fit through a two-and-a-half-square passage. Small vehicles retain a solid core at least half a square per dimension, or their original size if smaller. This reduced footprint follows the oriented chassis through the entire movement path, ignoring empty corners of the native selection box; center-path/native collision checks still apply, so it cannot cross a solid wall or closed door. Only wall clearance is reduced: token/vehicle collisions, movement reservations, Region boundaries and scene bounds use the full footprint.
- Non-wall clearance conservatively includes the vehicle body, changing native footprint, and intermediate turning angles. Large diagonal square footprints and the conservative turn envelope may reject visually possible turns. Own seated passengers are excluded; existing seat synchronization handles their placement.
- Vehicles and pedestrians reserve complete swept movement areas until their issued animations finish. Vehicle routes cannot cross other token bodies or active passages, and pedestrians cannot enter vehicle bodies or passages. Existing pedestrian-to-pedestrian crossing remains allowed.
- Vehicle driving replaces pedestrian side tracks; that option is hidden for vehicles. Waypoint/path pauses, Random distance preference, movement-time limits and speed remain available. Pauses and time limits take effect between complete driving steps.
- One retained A* search advances per scheduler tick, shared fairly between vehicles, with an 8 ms / 256-state slice target (checked between state expansions). Searches retain their frontier until a route is found, the reachable graph is exhausted, or a 40,000-state limit is reached. Time slicing never returns a partial route. Only an exhausted search can return the closest reachable approach; a search-limit result waits and reports the limit. Blocked vehicles retry after two seconds. Busy corridors can remain blocked; there is no traffic-priority or deadlock-resolution system.
- Collision avoidance governs Patrol-issued moves. Manual dragging, other modules, authority changes and newly placed obstacles can interrupt an already-issued animation; this does not install a global movement prohibition or traffic physics system. Each next step is checked again before submission.

## Execution and safety

- Only the active GM runs movement, and only on that GM's viewed scene. Other clients receive normal token document updates and animations. A GM must remain connected and viewing the scene.
- A game pause or any started combat associated with the scene suspends movement. Ending/deleting that combat or unpausing allows automatic continuation. A combat without a scene suspends all patrol scenes.
- Stop/combat pause prevents new movement segments; an already-issued animation can finish (up to roughly one second for Region roaming, or 250 ms for pedestrian routes, subject to client/network timing). Vehicles finish the current driving step; at slow speeds that can take several seconds.
- Manually moving/resizing a token invalidates its path. The next movement is planned from its current position. Unrelated token flag updates preserve its destination and progress. Seated vehicle riders do not run their own patrols.
- Switching scenes clears temporary routes/reservations. Saved enabled patrols resume when the active GM returns. Route progress is session-only and restarts from the first stop after reload or authority change.
- Normal token movement hooks still run, including Region and hazard hooks.

Validation is automated document/geometry and browser-fixture testing. Live Foundry v12/CPR and multiplayer checks remain pending, particularly animation smoothness, native Region movement events, and active-GM handoff.

- Patrol editor uses two columns: token, speed, pause controls, mode and detected vehicle/artwork front on the left; the last eight operations and a compact waypoint list with Place Waypoints on the right. History is temporary on the GM client that records it, refreshes while open, and clears on scene teardown. Existing independent pause ranges and automatic vehicle detection are preserved. Automated validation only; live Foundry verification pending.

- Patrol controller is 160 px wide by default, with tight spacing and a 22 px edit button. Long names/statuses truncate with full text on hover. Patrol names toggle individual Start/Stop, with status beneath the name and an adjacent pencil edit icon. The scene toggle uses the same semi-transparent button style; Configure patrol is removed. Scene pause continues to preserve individually stopped patrols.

- Vehicle Patrol permits moving 90-degree turns with an extra route cost equivalent to three grid spaces, favoring modestly longer routes with 45-degree turns. Intermediate body clearance is checked across the full turn. Stationary fallback still turns in 45-degree steps.

- Vehicle wall clearance now follows movement and rotation in swept intervals of at most 7.5 degrees, instead of applying the largest turning footprint to the entire move. Planning and the final movement guard use the same checks. Existing wall-edge tolerance, full-body token/Region/bounds checks and passage reservations remain enforced. Automated regression coverage includes turning away from a wall; the reported live scene still needs verification.

- Vehicle pathfinding rewrite: retained heading-aware A* with a priority queue replaces short searches that returned greedy partial approaches. Search slices target 8 ms / 256 states, one per tick with fair scheduling, and a 40,000-state total cap. Half-grid positioning and whole-grid moves share the same graph; reversing no longer has a three-step cap. Moving 45-degree turns are preferred over 90-degree turns; stationary turns have a high cost. Wall collision uses swept oriented chassis geometry with up to a quarter grid square of edge clipping per side and a nonzero core, independent of empty diagonal selection-box corners. Full native/body footprints still govern token, Region and scene-bound checks. The planner, final write guard, arrival-heading checks and swept movement reservations agree. Patrol supplies explicit center-preserving position/size/rotation updates, so manual vehicle rotation behavior is unchanged. Static geometry edits invalidate retained searches; dynamic movement is rechecked before each step. This supersedes earlier three-phase, whole-grid and whole-maneuver rectangle routing. Automated checks only; the reported live scene remains unverified.
