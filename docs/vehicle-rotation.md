# Vehicle rotation

Only scene tokens stamped `CreatedByVehicleTools` when spawned from **SceneTools / Vehicle Templates** receive these controls. Mooks, ordinary vehicle Actors, and unrelated tokens keep native behavior. Moving an Actor into the folder later does not mark its existing tokens.

Right-click the vehicle to open its Token HUD:

- **Turn left / right:** 15 degrees; hold Shift for 5 degrees.
- **Crosshairs (gridless/hex only):** configure the rotation pivot. Adjust Across/Down until the white marker lies on the artwork's rear axle, then Save pivot. Cancel leaves the saved pivot unchanged.
- **Use token center:** set both coordinates to 50% for center rotation.

The initial pivot is 50% across and 75% down the unrotated token footprint. It assumes the artwork faces up at zero rotation. For sideways or downward-facing artwork, place the marker on the appropriate axle. Transparent padding is included in these coordinates; it does not have to match the vehicle body's edges. The marker follows the current rotation. Pivot calibration is saved on the individual token; changing it does not move the vehicle.

Native rotation gestures and rotation-only document updates use grid-anchored footprints on square grids and the configured pivot elsewhere. Position, angle, and footprint are persisted together. On square grids, a 2 by 3 footprint stays in the same grid cells through 30 degrees, becomes 3 by 3 at 45, and becomes 3 by 2 at 60. The pattern repeats each quarter turn. Fine turns enter a diagonal band 7.5 degrees either side of each diagonal (37.5 through just under 52.5 degrees around 45). The top-left grid corner stays fixed; only the dimensions change. Existing off-grid tokens snap to the nearest grid corner on their next turn. Gridless scenes retain the previous axle rotation and direct cardinal footprint swaps. The vehicle keeps the same artwork size across these changes. Square-grid turns keep the footprint snapped; continuous axle translation applies only off square grids. New default vehicle templates start at 2 by 3 squares; newly spawned vehicles save their unrotated artwork dimensions on the Token. Missing or invalid saved dimensions report an error; recreate that vehicle from a Vehicle Template.

Rotation locks, ownership, and paused-game restrictions apply to the HUD controls. Rapid HUD clicks run sequentially. Explicit move-and-rotate updates, resizes, and Undo retain their supplied positions. Player turns check Foundry's normal center-point wall collision; this is not a vehicle-body collision or driving-physics simulation. HUD turns apply immediately. Native gestures retain Foundry's animation behavior. The native selection footprint remains axis-aligned and uses a square diagonal step on square grids. This deliberately approximates diagonal vehicles.

Implementation uses Foundry v12's [pre-update hook](https://foundryvtt.com/api/v12/functions/hookEvents.preUpdateDocument.html) and native [Token size and collision APIs](https://foundryvtt.com/api/v12/classes/client.Token.html). Artwork uses Foundry's [native mesh resize API](https://foundryvtt.com/api/v12/classes/client.PrimarySpriteMesh.html#resize), fitted against saved unrotated dimensions instead of the current footprint. The native fit mode, texture scales, mirroring, and aspect ratio are retained. Saved dimensions survive reload and copying. An intentional token resize establishes a new artwork size. Square and gridless scenes can calculate dimensions while inactive; hex scenes retain their original footprint and require their rendered token size for axle rotation.

Local build, geometry/workflow tests, and browser fixtures validate the implementation. Live Foundry and multiplayer verification remains pending. Seats and passenger movement are not implemented by this change.

Vehicle boarding/exiting requests use transient module socket messages to the active GM. Requests, responses and duplicate tracking are kept in memory and expire; no request flag is saved on Tokens. The GM grants requests in order and rechecks ownership, availability and capacity; the requesting owner performs the native document writes and acknowledges completion before the next request. Timeouts, disconnects and GM handoffs report a failed confirmation without replaying old requests. Saved seat assignments/layouts remain Token data. GM layout edits run locally; boarding and exiting require an active GM. Startup and reconnect do not repair saved assignments. Vehicle deletion restores its riders as part of deletion, and explicit Exit restores a rider even if the vehicle is already missing.
